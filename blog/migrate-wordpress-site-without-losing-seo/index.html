How to Migrate a WordPress Site Without Losing SEO Rankings

By Tobi Arowosegbe · Technical SEO specialist, Lagos · Updated August 2026

Migrations — new hosting, a new domain, or moving from a subdomain to a root domain — are one of the most common ways businesses accidentally destroy months or years of SEO progress. The good news: done correctly, ranking loss is preventable, not inevitable.

Before you touch anything: create a full backup and a URL inventory

Export a full list of your current site's indexed URLs (Google Search Console's Coverage report, or crawl the site with Screaming Frog) before making any changes. You need this list to verify every important page survives the move with a working redirect.

If you're changing hosting only (same domain)

  1. Set up the site fully on the new host first, without pointing the domain there yet.
  2. Test thoroughly on the new host's temporary URL or by editing your local hosts file to preview it.
  3. Update DNS to point to the new host, and keep the old host active for 24–48 hours until DNS propagation completes everywhere.
  4. Verify the site loads correctly from multiple locations/networks before decommissioning old hosting.

If you're changing domains

This is the higher-risk migration. The critical step: 301 redirect every old URL to its corresponding new URL, one-to-one, not just a blanket redirect of everything to the new homepage. A blanket homepage redirect tells Google every old page is now the same page, which tanks rankings instead of preserving them.

  • Map old URL → new URL for every indexed page, especially your highest-traffic pages.
  • Set up 301 (permanent) redirects, not 302 (temporary) — the redirect type genuinely affects how Google treats the ranking transfer.
  • Update internal links across the site to point directly to new URLs, not through the redirect chain.
  • Submit the new domain as a property in Google Search Console and submit its sitemap.
  • Use the "Change of Address" tool in Search Console if you're moving between two already-verified properties.

After migration: monitor closely for 2–4 weeks

  • Watch Search Console's Coverage report for a spike in 404s or "not found" errors — that signals a missed redirect.
  • Check that your top pages are still ranking for their target keywords; some temporary fluctuation is normal, a total disappearance is not.
  • Confirm structured data, meta tags, and canonical URLs all migrated correctly and reference the new domain/URLs, not leftover references to the old one.
  • Re-verify Google Analytics and any conversion tracking is firing correctly on the new setup.
The single most common migration mistake I see: forgetting to update the canonical tag and internal links to the new URLs, leaving them pointing at the old domain even after redirects are in place. This confuses Google about which version is authoritative and slows the ranking transfer significantly.
